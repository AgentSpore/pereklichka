# Проверка MVP

Проверено 2 октября 2026 года. Код бота, очереди, планировщика и запуска
сервиса влит в `main` через [PR № 1](https://github.com/AgentSpore/pereklichka/pull/1),
коммит `3f236d4`. Его содержимое совпадает с проверенной веткой `feature/mvp`.
Авторизация Telegram проверена локально; серверный polling, доставка сообщений
и Яндекс Диалоги пока не проверены.

## Автоматические проверки

Полный прогон: **106 passed, 1 warning in 17.14s**. Интеграционные тесты
используют PostgreSQL 16 с миграциями Alembic. Предупреждение относится к
устаревающему использованию `httpx` в `starlette.testclient`.
SQLAlchemy `SAWarning` в этом прогоне считается ошибкой.

`ruff check`, `ruff format --check` и `ty check` прошли. Проверено 59 файлов
форматирования. После добавления проверки наличия записи очереди её отдельный
тест повторён: **1 passed in 3.46s**.

Проверены команды через Dispatcher aiogram, доступ к семье, гонки приглашений,
транзакции отчётов, повторная доставка, восстановление очереди и ежедневные
тревоги. Завершённая отметка подавляет ожидающие тревоги. Эскалация продолжает
работать после местной полуночи до следующего дедлайна. Отдельные проверки
покрывают часовые пояса, DST и остановку активных обработчиков до закрытия БД.

Независимое ревью нашло две ошибки: утечку задач при отмене polling и потерю
эскалации через полночь. Обе воспроизведены до исправления. Повторное ревью
исправлений замечаний не нашло; проверка цитат из замечаний прошла.

## Параллельные диалоги

Тест запускает 20 семей одновременно, по два родственника в каждой.
80 измеренных запросов завершают 20 отметок; повторные последние ответы
не создают дополнительных отчётов. В очереди остаются ровно 40 заданий,
каждое адресовано родственнику своей семьи.

В итоговом локальном прогоне ASGI и PostgreSQL: **p95 0,186 с, максимум
0,190 с**. Сеть Telegram, сеть Яндекса и запуск планировщика в этот замер
не входят. Этот результат не доказывает соблюдение лимита 4,5 с в Диалогах.

Проверка чувствительна к ошибке: при отключении получателей отчёта она падает
на `0 == 40`. Полный прогон исходного кода прошёл.

## Контейнерный стенд

Образ `pereklichka:mvp-final` собран из кода приложения `7783fb0`;
процесс работает от `10001:10001`. Проверены миграция `0004`, готовность API
и запрос `SELECT 1` к PostgreSQL.

Через настоящий локальный TCP выполнен диалог Алисы из четырёх запросов,
повтор последнего ответа и отказ `403` запросу с чужим ID навыка.
Максимальное время этих запросов составило 0,031 с. В отдельном замере
20 параллельных приветствий: p95 0,269 с, максимум 0,271 с.
Замеры используют синтетические данные и не включают сеть Яндекса.

После пересоздания контейнеров БД и API сохранились одна семья, одна
завершённая отметка и два задания отчётов. Токен бота не задан,
поэтому задания не отправлены в Telegram. Планировщик запустился
и остановился без ошибок и предупреждений в журнале стенда.
Временные контейнеры и том этого стенда удалены.

## Публичный стенд

2 октября 2026 года развёрнут `main`, коммит `3f236d4`, на
https://pereklichka.agentspore.com. HTTPS `/health` отвечает `200`; TLS проверен.
Приложение и PostgreSQL здоровы. Независимая проверка подтвердила UID `10001`,
миграцию `0004` и успешный `SELECT 1`; все восемь таблиц пробы бота пусты.

Через публичный HTTPS выполнены 10 синтетических приветствий Алисы,
до пяти одновременно: все ответы `200`, p95 и максимум 0,942 с.
Запрос с чужим ID навыка вернул `403`. Повторный замер планировался на 20 запросов
с параллельностью 10, но остановился на `429`: Caddy ограничивает POST-запросы
до 30 на IP за минуту. Число ответов `429` не подсчитано; замер не завершён
и не подтверждает ёмкость приложения. Ни один замер не включает
вызов из Яндекс Диалогов и не доказывает соблюдение их лимита 4,5 с.
Независимый одиночный запрос Алисы вернул `200` с корректным протоколом за
0,727 с; проверка чужого ID навыка повторно вернула `403`.

Caddy 2.11.2 перечитал конфигурацию через `SIGUSR1`; PID процесса не изменился.
Проверка существующего соседнего сервиса до и после обновления вернула `200`.
Карточка проекта AgentSpore пока не обновлена: `/deploy` отвечает `501`,
а действующий endpoint обновления карточки не найден.

## Проба бота на сервере

В контейнере `pereklichka-app-1` выполнены 22 вызова `Dispatcher.feed_raw_update`.
Проверены `/start`, `/help`, `/ward`, `/wards`, `/relatives`, `/code`, `/invite`,
`/order` и `/schedule`: 14 групп проверок прошли. Повторный старт и повтор
приглашения безопасны; настройки сохраняются. Групповой чат и доступ постороннего
к семье отклонены; неверные аргументы команд обработаны.

Для синтетического подопечного первая тревога создала одно задание первому
родственнику. При моделировании эскалации через 45 минут созданы два задания
всем родственникам.
Завершение отметки удалило ожидающие тревоги и создало ровно два отчёта
получателям своей семьи. Повтор завершения дополнительных отчётов не создал.

Все 22 вызова `SendMessage` перехвачены тестовой сессией; запросов в Telegram
не было. Проба выполнялась во внешней транзакции с точками сохранения.
После отката её записи отсутствуют в `families`, `relatives`, `wards`,
`link_codes`, `invitations`, `check_ins`, `silence_alerts` и `outbox`.
Это проверка обработчиков и БД; реальный polling и доставка ещё не проверены.

## Повторить

```bash
uv sync --locked
uv run ruff check .
uv run ruff format --check .
uv run ty check
uv run pytest -q -W error::sqlalchemy.exc.SAWarning
```

Нужен работающий Docker. Для Colima перед прогоном задайте
`TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock`.
Запуск контейнерного стенда описан в [deployment.md](deployment.md).

## Проверка с живыми сервисами

Файл токена передан и установлен на сервере. Локальный запрос `getMe`
подтвердил `ok=true`, `is_bot=true` и имя `@PereklichkaAppBot`; токен действителен.
На сервере соединение с Telegram по IPv4 истекает по таймауту,
IPv6 недоступен. `getMe` из образа приложения завершился
`TelegramNetworkError` с причиной `TimeoutError`; серверная авторизация
и polling не проверены. Приложение не пересоздано, API и БД остаются здоровы.

Пока не подтверждены доставка в настоящий Telegram, черновик навыка и тестовый
чат Диалогов. Для продолжения нужны исходящий доступ сервера к Telegram
и ID навыка вместо `SKILL_ID=preview-local`. Секреты не передаются в чат.
