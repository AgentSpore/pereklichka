# Перекличка: ручные запросы удаления и отзыва

05.10.2026 · v1.0 · PRD-10 установлен; процедура проверена локально, ручные production-операции не исполнялись.
Оператор: Roman Konnov, [@exzentttt](https://t.me/exzentttt). Пересмотреть до: 12.10.2026.

Пользователь обращается лично к оператору. Оператор приватно проверяет личность, право на данные и точный объём запроса; затем согласует окно остановки приложения и выполняет ограниченную транзакцию. Скрипты не запускаются ботом и не означают автоматическое удаление. Версия PRD-10 установлена 05.10.2026; политика доступна публично. Перед каждой операцией повторно проверьте текущую версию и способ остановки именно этого развёртывания.

## Как выбрать операцию

| Запрос | Операция | Что сохраняется |
|---|---|---|
| Прекратить новые отметки одного близкого | Отзыв согласия подтверждённого подопечного | Завершённая история отметок |
| Удалить подтверждённую семью целиком | Удаление семейных данных | Данные других семей; сообщения, уже отправленные в Telegram |
| Удалить данные только одного человека | Сначала уточнить объём приватно | Частный запрос не разрешает автоматически удалить всю семью |

Не просите пользователя присылать ответы о здоровье, токены или секреты в публичные комментарии. Имя семьи или сообщение из чата сами по себе не подтверждают право удалить её целиком. Идентификатор подопечного/семьи устанавливается оператором приватно и не публикуется вместе с результатом.

## До транзакции

PO-01. Подтвердите личность, цель, объём и выбранную операцию; согласуйте с пользователем то, что останется после отзыва. Для удаления всей семьи нужно отдельное подтверждение этого объёма.

PO-02. Запланируйте окно остановки приложения. Должны быть остановлены входящие запросы Алисы, Telegram polling, worker очереди и scheduler. Они могут находиться в одном процессе; убедитесь, что других работающих экземпляров нет. Не удаляйте данные параллельно с приложением.

PO-03. Применяйте существующий способ остановки этого конкретного развёртывания. Сохраните незнакомые Compose overrides, настройки и чужие файлы. Этот документ не предоставляет непроверенных production-команд и не разрешает автоматическую остановку.

PO-04. Подключение к БД выполняет процесс psql через уже настроенное окружение. Не печатайте пароль, строку подключения, окружение или содержимое файлов секретов. Вывод операции содержит только количества; не добавляйте списки людей или ответы.

## Две транзакции

Отзыв `deploy/revoke-consent.sql` работает с одним подтверждённым ward UUID. Он снимает device и consent/version, удаляет коды привязки, неудачные попытки для текущего device, незавершённые отметки и ожидающие задания его отчётов/тревог. Завершённые отметки остаются. После отзыва новая привязка и согласие потребуются повторно.

Удаление `deploy/delete-family-data.sql` работает с подтверждённым family UUID. Перед удалением семьи удаляются связанные задания очереди по её получателям и доменным событиям, а также относимые к её устройствам неудачные попытки; зависимые семейные записи удаляются через FK CASCADE. Другую семью операция не затрагивает.

Аргументы `ward_id` и `family_id` сверены с реальными скриптами. Ниже запускается только одна выбранная операция из корня checkout, после PO-01 по PO-04. `CONFIRMED_WARD_UUID` либо `CONFIRMED_FAMILY_UUID` уже содержит приватно подтверждённый UUID цели; это не пароль. Окружение подключения psql настроено отдельно, его значения не выводятся.

```bash
psql -X -v ward_id="$CONFIRMED_WARD_UUID" -f deploy/revoke-consent.sql
```

Либо, только для отдельно подтверждённого удаления всей семьи:

```bash
psql -X -v family_id="$CONFIRMED_FAMILY_UUID" -f deploy/delete-family-data.sql
```

Неизвестная цель, неверный UUID или ошибка должны приводить к откату транзакции. Примеры соответствуют реальным psql-проверкам на синтетическом PostgreSQL 16: scope двух семей, rollback и повторы; финальный scoped 14 passed, независимо у координатора 14 passed. Это не разрешение автоматически исполнять их в production.

## После транзакции

PO-05. Проверьте итог только по безопасным counts и коду завершения процесса. При ошибке не объявляйте запрос выполненным; неизвестный результат сверяется до решения о повторе.

PO-06. После успешного COMMIT или подтверждённого отката возобновите приложение существующим способом и проверьте доступность. Перезапуск очищает прежние черновики в памяти. Сообщите пользователю фактически выполненный объём и ограничения. В записи оператора не храните содержимое ответов или секреты.

Не обещайте удаление уже доставленных Telegram-сообщений. Попытки безопасности без установленной связи с устройством/семьёй нельзя уверенно приписать этому запросу. Сроки резервных копий и автоматического хранения в этом документе не установлены; неизвестное нельзя заменить обещанием удаления по расписанию.

Пример нормы: Given оператор подтвердил только отзыв одного подопечного, When готовится операция, Then скрипт удаления всей семьи не запускается. Это ограничение выбора, не описание уже выполненного production-запроса.
